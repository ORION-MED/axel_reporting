# Форма отчёта из региональной ГИС: закрытые случаи

```
python tools/gis-report-form/build_gis_form.py [справочник_МО.xlsx] [результат.xlsx]
```

Без аргументов берёт справочник признаков МО от 24.08.2026 и пишет
`AXEL_контекст/24.08/AXEL_форма_отчёта_из_ГИС_закрытые_случаи_2026-08-24.xlsx`.

## Зачем

ВКС 24.08.2026, задача Д-10. Николай Ермаков: «вот здесь третья колонка
появляется — законченные случаи по данным ГИС… он может быть краснее красного».
Методолог назвала способ получить данные: «регион может заказывать отчёт вендору —
мы даём форму, по которой нам было бы удобно его подгружать, техподдержка МИАЦ
запрашивает по этой форме отчёт и загружает в программу».

Форма — это и есть наша часть договорённости. Заполняет её не методолог,
а вендор региональной ГИС по заявке МИАЦ.

## Главное решение: виды случая берутся из ТПГГ, а не придумываются

Смысл третьей колонки — сравнить три числа по одной и той же совокупности:
план по терпрограмме, зарегистрированные СЭМД и фактически закрытые случаи.
Если состав случаев в отчёте ГИС не совпадёт с тем, по которому считается
знаменатель, сравнивать будет нечего.

Поэтому `CASE_TYPES` — это ровно листы ТПГГ из `semd-volume-ratio.config.ts`,
а «Код вида случая» совпадает с `sheet_code` в `reporting_tpgg_plan_values`:

| Показатель | Листы ТПГГ | Видов случая |
|---|---|---|
| 6.1.3.2.8 — эпикриз амбулаторный | 2, 3, 4 | 3 |
| 6.1.3.2.9 — профосмотры и диспансеризация | 3.2 … 3.9 | 8 |
| 6.1.3.2.10 — эпикриз стационарный | 5, 6, 7, 8, 9 | 5 |
| 6.1.3.2.11 — карта вызова скорой | 1 | 1 |

Итого 17 видов случая. **Менять этот перечень нельзя без правки конфигурации
показателей** — иначе импортёру не с чем будет сводить.

## Что внутри

| Лист | Назначение |
|---|---|
| **Как заполнять** | инструкция вендору: что считать закрытым случаем, помесячно или нарастающим итогом, чем ноль отличается от пустой ячейки |
| **Закрытые случаи** | обязательный. 37 МО × 17 видов = 629 строк, заведены заранее; двенадцать колонок месяцев и годовой итог формулой |
| **По подразделениям** | необязательный. Те же колонки плюс OID подразделения, ID и адрес здания. 400 пустых строк с выпадающими списками |
| **Справочник МО** | 37 организаций с OID по ФРМО |
| **Виды случая** | расшифровка 17 кодов и привязка к показателям |
| **Контроль заполнения** | заполнено строк, всего случаев, нечисловые и отрицательные значения, суммы по каждому показателю |

## Почему помесячно, а не нарастающим итогом

Из помесячных чисел накопительный итог считается, из накопительного помесячные —
только разностями, и любая опечатка в одном месяце портит два. Плюс Д-9 (кривая
динамики) нужен именно помесячный ряд: весь смысл графика в том, чтобы увидеть
ровную линию против декабрьского всплеска.

## Почему строки заведены заранее

629 строк со всеми сочетаниями — компромисс. Вендору, который генерирует отчёт
машиной, они не мешают (перегенерирует по своему запросу), а человеку, который
заполняет руками, не нужно ничего заводить. В инструкции отдельно сказано,
что пустая строка у неоказываемой помощи — не ошибка.

## Лист по подразделениям — на будущее

Обязательным не сделан: Д-10 считает третью колонку по медорганизации целиком.
Но если ГИС отдаёт разбивку, она сразу закрывает Д-17 («провал до отделения»,
версия 2.0) без второго круга согласований. Колонки ID и адреса здания названы
так же, как в сводном отчёте РЭМД по подразделениям, — там они уже есть,
и в тех же терминах методолог определила ТВСП на созвоне.

## Тонкость с формулами контроля

Суммы по показателям считаются `SUMIF` по колонке годового итога, а не
`SUMPRODUCT` по диапазону месяцев: признак показателя — одна колонка, месяцы —
двенадцать, поэлементно они не перемножаются, размерности не совпадают.
`SUMIF` заодно игнорирует пустую строку, которую годовой итог возвращает
у незаполненных строк.
