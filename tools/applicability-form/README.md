# Форма условий обязательности: две колонки перечней МО

```
python tools/applicability-form/build_form.py <матрица.xlsx> <справочник_МО.xlsx> <результат.xlsx>
python tools/applicability-form/simulate_check.py <результат.xlsx>
```

Без аргументов оба сценария работают с редакцией от 24.08.2026 —
пути зашиты в начале файлов.

## Что делает

Пересобирает лист «Форма условий», вставляя после «Дополнительного условия»
две колонки перечней медорганизаций:

| Колонка | Смысл |
|---|---|
| **H — «Только эти МО»** | строка действует исключительно на перечисленные МО |
| **I — «Все МО, кроме этих»** | строка действует на всех, кроме перечисленных |

Решение ВКС 24.08.2026 по вопросу В-04. Раньше перечень писался свободным
текстом в «Дополнительном условии» («если МО - Бюро СМЭ»), и три наименования
из него — «Санаторий», «Диспансер», «Психоневрологический диспансер» — три
недели не сопоставлялись ни с одной из 37 МО и держали весь расчёт.

## Заголовки намеренно нейтральные

Не «Обязателен только этим МО», хотя именно так это звучало на созвоне.
Перечень применяется к строке целиком, а решение строки бывает и
«не обязателен»: у вида 85 стоит «не обязателен» с перечнем из шести
узкоспециализированных МО, и заголовок со словом «обязателен» прочитался бы
ровно наоборот. Так же это устроено и в движке
(`applicability-matrix-import.service.ts`): условие решает, **применяется ли
правило к этой МО**, а `requirementStatus` — **что правило говорит**.

## Что ещё делает сценарий

- **Выпадающий список** на `H5:I582` из именованного диапазона
  `MO_SHORT_NAMES` — 37 кратких наименований из колонки «краткое наименование
  для отображения в сервисе» справочника признаков МО. Список кладётся
  на лист «Справочник ФРМО», колонка W.
- **Ввод не запрещён** (`showErrorMessage=False`): перечень из нескольких МО
  пишется через запятую, а список Excel такую строку целиком не пропустил бы.
  Корректность проверяет формула, а не валидация.
- **Предзаполняет колонки** из старого текста «если МО …» — 25 строк.
  Исходный текст остаётся на месте для сверки.
- **Возвращает виду 47** условие «Обязателен для МО с прикреплённым населением»,
  если оно пустое: в редакции методолога от 24.08 оно пропало, а без него
  вид становится обязателен 33 МО вместо 15 и ГКУ «КОПНБ» откатывается
  со 100 % на 13 из 14.
- **Переписывает «Проверку строки»** (колонка K): к прежним «ГОТОВО» и
  «НЕ ЗАПОЛНЕНО» добавились «ОШИБКА» (обе колонки сразу либо имя не из
  справочника) и «НУЖНО РЕШЕНИЕ» для «условно» и нераспознанного перечня.
  Нераспознанный перечень проверяется **раньше** «условно»: у видов 90 и 142
  стоит и то и другое, и при обратном порядке настоящий блокер всплыл бы
  только вторым заходом.
- **Дополняет «Контроль заполнения»** строками «Строк с перечнем МО»
  и «Ошибок и нерешённых строк».
- **Убирает «условно» из выпадающего списка «Решение»** (`RULE_STATUSES`
  сужается с `$U$3:$U$6` до `$U$3:$U$5`). Решение ВКС: «зачем нам тогда решение
  "условно", если мы его заменим». В девятнадцати существующих строках значение
  остаётся — Excel проверяет ввод, а не записанное.
- **Переписывает подпись под шапкой** (строка 3): она называет новые колонки,
  иначе перечень МО по привычке уходит в «Дополнительное условие».
- **Дописывает лист «Как заполнять»** — раздел про две колонки.

| `ГКУ КОПБ` | КОПНБ | иного кандидата среди 37 МО нет |
| `Бюро СМЭ` | КОБСМЭ | |

| `ГСП` | МАУЗ ГСП | |

«Диспансер» (90), «Психоневрологический диспансер» (142).

## Проверка

`simulate_check.py` повторяет формулу колонки K на Python. Нужен потому, что
openpyxl формулы не считает: в сохранённом файле их значения появятся только
при открытии в Excel, а знать заранее, что увидит методолог, надо сейчас.

На редакции от 24.08.2026 ожидается: 186 «ГОТОВО», 17 «ГОТОВО: ДЛЯ ВСЕХ»,
19 «условно», 5 «перечень не распознан», ошибок 0.

## Сдвиг колонок ничего не сломал

Проверено прогоном настоящего парсера (`loadApplicabilityMatrixWorkbook`)
на файле до и после: 220 правил, те же статусы, условия и основания,
одно предупреждение — и единственное отличие в том, ради чего всё делалось:
вид 47 получил условие `attached_population` вместо `none`.

Так вышло потому, что парсер ищет колонки по названиям заголовков, а формулы
«Проверки строки» ссылаются только на A..G — левее места вставки. На листе
«Контроль заполнения» правится единственная ссылка `I` → `K`.
