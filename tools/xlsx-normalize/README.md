# Нормализация XLSX перед загрузкой

```
python tools/xlsx-normalize/unprefix.py <исходный.xlsx> <нормализованный.xlsx>
```

## Когда нужно

Импорт падает с «Не удалось прочитать Excel-файл …», хотя файл открывается
в Excel и читается openpyxl. В логах ExcelJS при этом видно
`Cannot set properties of undefined (setting 'sheetNo')` или
`Cannot read properties of undefined (reading 'company')`.

Причина — не содержимое, а сериализация. Некоторые редакторы сохраняют книгу
с префиксом пространства имён SpreadsheetML (`<s:workbook>`, `<s:sheet>`, `<s:c>`)
вместо пространства по умолчанию. ExcelJS сравнивает имена тегов буквально,
листы не регистрируются, и загрузка падает.

Так пришла матрица применимости от 18.08.2026
(`AXEL_контекст/15.08/8_Матрица_применимости_145_видов_от_13.08.xlsx`).

## Что делает

Переписывает только сериализацию XML: префикс убирается, пространство имён
становится основным. Ни одна ячейка не трогается.

**Проверять равенство обязательно** — тем же способом, что и всё остальное
в проекте, сверкой, а не доверием:

```
python <сверка ячеек> <исходный.xlsx> <нормализованный.xlsx>
```

Пересохранение через `openpyxl.save()` для этого **не годится**: формулы
теряют кэшированные значения, и колонка «Проверка строки» вместе с листом
«Контроль заполнения» приходят пустыми.

## Правильное решение

Попросить поставщика файла пересохранить книгу из Excel («Сохранить как» →
`.xlsx`). Скрипт — обходной путь на один раз, а не часть порядка загрузки.
